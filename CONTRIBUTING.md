# Contributing

Thank you for considering a contribution to an upTools project. Bug reports, ideas and pull requests are all welcome.

## Reporting issues

Before opening an issue, search the existing ones to avoid duplicates. When you open one, include steps to reproduce, the expected and actual behaviour, your environment, and screenshots or logs where they help. See [SUPPORT.md](SUPPORT.md) for details.

Security vulnerabilities go through our [Security Policy](SECURITY.md), never a public issue.

## Making changes

1. Fork the repository and create a branch from `main`.
2. Keep each change focused: one fix or feature per pull request.
3. Follow the existing code style of the project.
4. Add or update tests when you change behaviour, and make sure all tests pass.
5. Update the documentation (README, changelog) when behaviour changes.
6. Write clear commit messages that explain why, not only what.

```bash
git clone https://github.com/YOUR-USERNAME/REPOSITORY-NAME.git
cd REPOSITORY-NAME
git remote add upstream https://github.com/uptools-io/REPOSITORY-NAME.git
git checkout -b fix/short-description
```

## Pull requests

1. Rebase on the latest `upstream/main` before opening the pull request.
2. Describe what the change does and why, and reference related issues.
3. Respond to review feedback. A maintainer merges once the change is approved.

By contributing, you agree that your contribution is licensed under the license of the repository you contribute to.

## Questions

Open an issue in the repository, or write to [support@uptools.io](mailto:support@uptools.io).

Please follow our [Code of Conduct](CODE_OF_CONDUCT.md).
